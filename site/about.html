About and contact

Truth from hardware, not from memory.

Aletheon is an open-source project that makes embedded-systems AI and tooling accountable to evidence: a firmware assistant that cites the datasheet text behind every register, voltage and timing it states, and a set of free browser tools for learning and testing embedded designs.

What it is

  • A VS Code extension and an MCP server that read datasheets and register maps, and audit their own answers: a claim that cannot cite evidence containing its value is flagged. See the home page.
  • A Chip Atlas and a Parts catalog built from public sources, with datasheet and vendor links.
  • Simulators: the Device Lab, the IoT Bench, the Logic Analyzer and the Scenario Labs.

Rules it holds itself to

  • Evidence first. A hardware fact on this site is either tied to a page-cited quote from the vendor's datasheet, or visibly labelled as derived, assumed or weaker.
  • No copying. Facts are written in our own words with short quotes (never more than 15 words) as evidence. Datasheet PDFs and figures are not hosted here.
  • Honest simulators. Every simulator says it is a behavioral model, not a circuit simulation, and lists what it leaves out. See the list.
  • No invented endorsements. There are no testimonials, customer logos or partner claims on this site because there are none to show. Aletheon is independent and is not affiliated with or endorsed by any chip vendor.
  • Local-first. The tools run in your browser. No accounts, no analytics, nothing uploaded. See Privacy and legal.

Who maintains it

Aletheon is created and maintained by Dinesh Karnati and released under the Apache-2.0 license. It is an early-stage project (version 0.1.1, alpha). Contributions are welcome; see Contributing and the code of conduct.

Contact

  • Questions, bugs and ideas: open a GitHub issue. This is the project's only public contact channel.
  • Source code: github.com/denishkarnati/Aletheon.

Report a security problem

Please do not open a public issue for something exploitable. Use GitHub's private vulnerability report form, and include steps to reproduce, the affected version and your assessment of the impact. The full policy, including what the project defends against and what it does not, is in SECURITY.md. This is a volunteer-run project: we aim to acknowledge a report within 5 working days, and there is no bounty program. A machine-readable copy of this is at /.well-known/security.txt.

Trademarks and data

Part names and numbers belong to their owners and appear only to identify parts. The parts catalog data is derived from the KiCad symbol libraries and shared under CC BY-SA 4.0. The Chip Atlas is built from public board manifests listed on its page.
