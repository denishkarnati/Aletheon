001 / The problem

A wrong register looks exactly like a right one.

Models write confident firmware from memory. A bad address doesn't raise an error. It quietly writes to the wrong place. Same question, two standards:

Typical assistant · illustration

“The UART data register is at 0x40034004, the core runs at 266 MHz, and it resets to 0x00000000.”

✗ no source cited for any value
✗ plausible, confident, and wrong
✗ nothing to check it against
A made-up answer written to show the failure mode. Not a quote from any product.

Aletheon

“UARTDR is at 0x40034000 E3. The core's maximum clock is 133 MHz E9, datasheet page 10.”

✓ each value appears in the evidence it cites
✓ source, trust class and file hash recorded
✓ anything unproven is marked UNVERIFIED
Evidence ids refer to ledger entries. The audit checks that the cited text contains the value.
002 / How it works

Evidence first. Then the answer.

01

An evidence ledger

Every tool result becomes a numbered entry with its source, the SHA-256 of the exact file, and a timestamp. It lives in your project, not on a server.

02

Trust classes

A vendor PDF, a community mirror and a serial capture are not equal. The ledger says which is which, and answers that rest only on weak sources are flagged.

03

A claim audit

Each sentence stating a hardware value must cite an entry whose text contains it. Uncited values, invented ids and citations that prove nothing are caught.

04

Real hardware is the last word

Build output, flash logs and serial captures are recorded as measured evidence. Writing, flashing and external tools always ask first.

    007 / Install

    Running in two minutes.

    install the extension 
    # download aletheon-0.1.0.vsix from github.com/denishkarnati/Aletheon/releases/latest
# (or build it yourself: git clone, then npm install && npm run vsix), then:
$ code --install-extension aletheon-0.1.0.vsix
# Aletheon: Set AI Provider API Key → pick a board in the status bar
    build the MCP server 
    $ git clone https://github.com/denishkarnati/aletheon
$ cd aletheon && npm install && npm run build
# then add to your client's MCP config:
{ "mcpServers": { "aletheon": {
    "command": "node", "args": ["/path/to/aletheon/dist/mcp.js"],
    "env": { "ALETHEON_ROOT": "/path/to/your/firmware", "ALETHEON_BOARD": "rpi-pico" } } } }
    check it works 
    $ npm test
$ npm run bench:grounding -- --list
# 20 questions, ground truth computed from the RP2040 register file

    You also need your own toolchain (PlatformIO, arduino-cli or ESP-IDF) to build and flash. Serial capture needs Python with pyserial. Node.js 20 or newer.

    010 / Questions

    Straight answers.

    Can it still be wrong?

    Yes. The audit checks that cited evidence contains the value a claim states. It does not prove the model's reasoning is sound, and a datasheet can itself be wrong. Compile it, flash it, measure it. Aletheon records those results as evidence too.

    Does my data leave my machine?

    Documents, parsed register maps, vectors and the ledger stay in your project's .aletheon folder. Text that a tool returns is sent to the model provider you configure so it can answer. Use a local model through Ollama if that is not acceptable. There is no telemetry.

    Will it flash my board on its own?

    No. Writing files, generating headers, flashing and running external analysis each ask for your approval first, and the MCP server denies them unless you opt in. Document downloads also refuse private and internal addresses.

    Which boards work today?

    The registry has the Raspberry Pi Pico (RP2040), ESP32 and ESP32-S3, STM32 Nucleo-F401RE, nRF52840 DK and Arduino Uno. Register maps are tested for the first four chips. Adding a board is one small registry entry.

    Where do the datasheets come from?

    They are downloaded from the vendor, or a mirror, onto your machine when you ask. This project does not redistribute vendor documents. Each source is labelled vendor-official, community-mirror or user-supplied, and its SHA-256 is recorded. The Parts catalog and Device Lab follow the same rule: part lists come from KiCad's open libraries (CC BY-SA 4.0), and each device model is written in our own words with short quotes of 15 words or fewer that a script checks against the cited page of the vendor's PDF. Vendor links open the vendor's own copy.

    Is it free?

    The core is open source under Apache-2.0. You bring your own model key, or run a local model. Team features may become a paid layer later.

    Is it affiliated with another product?

    No. It is an independent project. Product and company names mentioned are the property of their owners.
